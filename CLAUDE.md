# CLAUDE.md — clinic-voice-agent

Hindi/English phone agent that books clinic appointments, plus a caller simulator
that scores every change and blocks regressions in CI.

## Roles (read this first)

- **Cyril is the senior engineer.** He owns the design, the decisions, and every merge.
- **Claude is the junior engineer.** You propose, implement small pieces, write tests,
  and report honestly. You do not make architecture decisions on your own.
- If a task needs a decision not already recorded in `docs/decisions/`, STOP and ask.
  Offer 2–3 options with trade-offs; do not pick silently.

## Stack (decided — see ADRs before changing)

- Python 3.11, `uv` for envs, `ruff` (lint+format), `pyright` (types), `pytest`.
- Pipecat for the realtime audio pipeline; LangGraph only for dialogue logic.
- vLLM (OpenAI-compatible endpoint) for the LLM; faster-whisper / IndicConformer for STT;
  CPU-first TTS. Silero VAD + Smart Turn for turn-taking.
- SQLite clinic backend with deterministic seed data.
- Hardware: single RTX 4060 **8 GB VRAM**. Every GPU change must state its VRAM cost.

## Commands

```bash
make setup        # uv sync, pre-flight checks
make check        # lint + types + unit tests  (Gate G1 — must pass before any commit)
make test         # pytest -q
make eval-text    # simulator, text mode, all scenarios
make eval-audio   # simulator, audio mode, nightly subset
make bench        # latency + VRAM benchmark -> results/*.json
make gate         # compare latest eval vs ci/baseline.json; non-zero exit on regression
```

## Rules of engagement

1. **Small diffs.** One concern per commit, aim < 200 changed lines. If a change grows,
   stop and propose a split. Test files and generated files may exceed 200 lines in one
   commit if the commit body says so; code stays under 200.
2. **Tests first for logic.** Tools, scorers, date parsing, and the gate script get unit
   tests before or with the code. Never weaken or delete a test to make it pass — report it.
3. **No invented numbers.** Never write a latency, WER, or score into any doc by hand.
   Numbers come from `results/*.json` produced by a script, with the command and commit hash.
4. **No silent dependencies.** Adding a package needs a one-line reason in the commit body.
5. **Explainable code.** Prefer plain, boring code over clever code. No abstraction until
   the third use. Every module has a top docstring saying what it does and why it exists.
6. **Timezone is Asia/Kolkata.** All slot logic uses timezone-aware datetimes.
7. **Interruptions are a correctness issue.** A booking must never be committed from a turn
   that was cancelled by barge-in. Any change to the turn/LLM path must keep that test green.
8. **Don't touch** `ci/baseline.json` unless the task explicitly says "rebaseline".
9. **Git:** you may stage and propose commit messages; Cyril approves commits. Never push,
   never rewrite history, never `--no-verify`.
10. **When stuck after two attempts**, stop, write what you tried in `docs/FAILURES.md`
    (draft entry), and ask.
